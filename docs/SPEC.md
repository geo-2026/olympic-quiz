# 통합사회 올림픽 형성평가 게임 — 요구사항 명세서

> **이 문서의 사용법 (Claude Code)**
> 1. 새 프로젝트 폴더(예: `olympic-quiz`)를 만들고 이 파일을 `docs/SPEC.md`로 넣습니다.
> 2. 앞서 받은 경기 장면 키트 6개의 압축을 풀어 `public/scenes/` 아래에 넣습니다(10장 참고).
> 3. Claude Code에서 다음과 같이 요청합니다.
>    `docs/SPEC.md를 읽고 17장의 개발 단계 순서대로 만들어 줘. 단계마다 완료 기준을 확인하고 다음 단계로 넘어가 줘.`
> 4. 이 문서에서 **[필수]**는 반드시 구현할 기능, **[선택]**은 시간이 되면 구현할 기능입니다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | 통합사회 올림픽 형성평가 (가칭) |
| 목적 | 통합사회 형성평가를 팀 대항 올림픽 경기로 진행해 참여도와 몰입감을 높임 |
| 대상 | 고등학교 1학년 한 학급(약 25~35명) |
| 사용 장소 | 교실(교사 PC + 프로젝터 화면, 학생 개인 휴대폰 또는 태블릿) |
| 팀 | **토끼팀**(분홍 `#ff8fb6`)과 **고양이팀**(주황 `#ffa64d`) |
| 핵심 흐름 | 학생 입장(학번·이름) → 자동 팀 배정 → 문항 풀이 → 문항마다 팀 점수 계산(정답률·입력 시간 반영) → **묶음 종목**은 3문항 점수를 합산해 경기 1회, **문항별 종목**은 문항마다 경기 1회 → 종목별 승자 → 최종 합계로 우승 팀 결정 |

### 1.1 종목 구성 [필수]

| 순서 | 종목 | 문항 번호 | 경기 방식 | 경기 실행 시점 |
|---|---|---|---|---|
| 1 | 줄다리기 | 1~3번 | **묶음 종목**: 3문항 점수 합산 → 한 판 당기기 1회 | 3번 문항 정답 공개 뒤 |
| 2 | 스키점프 | 4~6번 | **묶음 종목**: 3문항 점수 합산 → 점프 1회 | 6번 문항 정답 공개 뒤 |
| 3 | 스켈레톤 | 7~9번 | **묶음 종목**: 3문항 점수 합산 → 주행 1회 | 9번 문항 정답 공개 뒤 |
| 4 | 멀리뛰기 | 10~12번 | **묶음 종목**: 3문항 점수 합산 → 1차 시기 1회 | 12번 문항 정답 공개 뒤 |
| 5 | 양궁 | 13~22번 | **발별 종목**: 2문항 합산 = 1발 (총 5발, 20점 과녁) | 2문항마다 |
| 6 | 사격 | 23번 ~ 마지막 문항 | **문항별 종목**: 1문항 = 1발 | 문항마다 |

- **묶음 종목**(줄다리기, 스키점프, 스켈레톤, 멀리뛰기)은 3문항을 연달아 푼 뒤, 세 문항의 팀 점수(정답률·입력 시간 반영)를 합산해 경기를 한 번 치릅니다. 문항을 하나씩 풀 때마다 무대에 팀별 **누적 게이지**가 차오릅니다(3.1-6 참고).
- **문항별 종목**(양궁, 사격)은 문항마다 그 문항의 승리 팀이 그 발에서 이깁니다.
- 문항이 22개 이하이면 뒤쪽 종목은 있는 문항까지만 진행합니다. 예를 들어 문항이 16개라면 양궁은 4발만 쏘고 사격은 없습니다.
- 묶음 종목의 문항이 3개보다 적게 남으면(예: 문항이 11개라 멀리뛰기가 10~11번 두 문항뿐) 있는 문항만 합산해 경기를 1회 치르고, 화면에 "2문항 합산"이라고 표시합니다.
- 문항 수를 올리면 관리자 화면에 **종목 배정 미리보기 표**를 보여 줍니다(6.4 참고).

## 2. 사용 환경과 기술 스택

### 2.1 권장 스택 [필수]

| 구분 | 선택 | 이유 |
|---|---|---|
| 서버 | Node.js 20 + Express + **Socket.IO 4** | 교사 화면과 학생 화면을 실시간으로 동기화 |
| 화면 | HTML + CSS + 바닐라 JavaScript(ES 모듈), 빌드 도구 없음 | 수정과 배포가 간단함 |
| 엑셀 | **SheetJS(xlsx)**, 브라우저에서 읽기와 쓰기 | 문항 업로드, 템플릿 다운로드, 결과 내보내기 |
| QR 코드 | `qrcode` npm 패키지 | 학생 입장 주소를 QR로 표시 |
| 3D 경기 장면 | 기존 장면 키트 6개(three.js r128 포함) | 이미 만들어 둔 블록 캐릭터 경기 장면을 재사용 |
| 저장 | 서버 메모리 + `data/` 폴더의 JSON 스냅샷 | 서버가 재시작돼도 진행 중인 게임을 복구 |
| 테스트 | Node 내장 `node:test` | 채점·힌트·엑셀 변환 단위 테스트 |

### 2.2 실행과 배포 [필수]
- **방법 A (권장): Render 웹 서비스.** GitHub 저장소를 Render에 연결해 배포합니다. Socket.IO(WebSocket)를 지원합니다. 무료 플랜은 15분 동안 접속이 없으면 잠들기 때문에, 수업 1~2분 전에 관리자 화면을 먼저 열어 깨웁니다. README에 이 내용을 적습니다.
- **방법 B: 교사 PC에서 실행.** `npm start`로 실행하고, 학생은 같은 와이파이에서 `http://교사PC주소:3000/play`로 접속합니다. Windows 방화벽 허용 방법을 README에 적습니다.
- 환경 변수: `PORT`(기본 3000), `ADMIN_PIN`(관리자 비밀번호, 필수), `DATA_DIR`(스냅샷 폴더, 기본 `./data`).

### 2.3 지원 기기
- 관리자: Windows PC의 크롬 또는 엣지, 1920×1080 프로젝터 화면 기준.
- 학생: 안드로이드와 iOS 휴대폰 브라우저(세로 화면, 360px 폭부터). 학생 화면에는 3D 장면을 넣지 않습니다(성능과 데이터 절약).

## 3. 화면 구성

| 주소 | 화면 | 사용자 |
|---|---|---|
| `/admin` | 관리자(교사) 화면: 게임 진행 조작판과 프로젝터용 무대 | 교사 |
| `/play` | 학생(사용자) 화면: 입장, 문제 풀이, 결과 | 학생 |
| `/display` [선택] | 프로젝터 전용 화면(조작 버튼 없음). 관리자 화면을 교사 노트북에만 띄울 때 사용 | 교사 |

### 3.1 관리자 화면 `/admin` [필수]
1. **로그인:** `ADMIN_PIN` 입력. 성공하면 브라우저 세션에 토큰을 저장하고, 새로 고침해도 로그인과 진행 상태가 유지됩니다.
2. **방 만들기:** 4자리 방 코드를 만들고, 입장 주소(`/play?room=1234`)와 QR 코드를 크게 표시합니다.
3. **문항 관리:** 엑셀 업로드, 템플릿 다운로드, 문항 미리보기, 오류 표시, 종목 배정 미리보기(6장).
4. **학생과 팀 관리:**
   - 토끼팀과 고양이팀 명단을 두 열로 보여 줍니다. 각 학생에 학번, 이름, 접속 상태(초록 점은 접속, 회색 점은 끊김)를 표시합니다.
   - `팀 무작위 다시 섞기`(게임 시작 전에만 가능), 학생을 다른 팀으로 옮기기(이름 옆 `⇄` 버튼), 학생 내보내기.
   - 팀 인원 수와 인원 차이를 표시합니다(차이가 2명 이상이면 경고).
5. **진행 조작판** (상태에 따라 누를 수 있는 버튼만 활성화):

   | 버튼 | 동작 |
   |---|---|
   | `게임 시작` | 대기실 → 1번 문항 준비 |
   | `문제 시작` | 현재 문항을 모든 학생에게 동시에 보내고 타이머 시작 |
   | `지금 마감` | 시간이 남아도 제출을 마감 |
   | `정답 공개` | 정답, 정답률, 평균 시간, 팀 문항 점수, 문항 승리 팀 표시 |
   | `경기 보기` | 무대에서 경기 장면을 재생(결과는 이미 정해져 있음). **묶음 종목은 그 종목의 마지막(3번째) 문항 정답 공개 뒤에만**, 문항별 종목은 문항마다 켜짐 |
   | `다음 문제` | 다음 문항으로. 묶음 종목의 1·2번째 문항에서는 정답 공개 뒤 바로 켜짐. 종목이 바뀌면 먼저 **종목 전환 화면**(11장) |
   | `게임 종료` | 문항이 남아 있어도 게임을 끝내고 최종 결과로 이동(12장) |
   | `소리 켜기/끄기`, `전체 화면` | 보조 기능 |

   - `게임 종료`는 실수로 누르지 않도록 빨간색으로 오른쪽 끝에 따로 둡니다. 누르면 화면 안 확인 상자("남은 문항 N개가 있어요. 지금 종료할까요?" `종료` / `취소`)가 뜹니다. 브라우저 `confirm()`은 쓰지 않습니다.
   - [선택] `자동 진행` 모드: 정답 공개 → 경기 보기 → 다음 문제를 정해진 간격으로 자동으로 이어 갑니다(교사는 `문제 시작`만 누름).
6. **무대(프로젝터 영역):** 화면의 넓은 부분을 차지합니다. 상태에 따라 내용이 바뀝니다.
   - 대기실: QR 코드, 방 코드, 팀별 입장 인원, 블록 캐릭터.
   - 문제 진행: 문제, 보기, 큰 타이머, 팀별 제출 인원(예: "토끼팀 12/15 제출"). **누가 무엇을 골랐는지는 표시하지 않습니다.**
   - 정답 공개: 정답, 팀별 정답률·평균 정답 시간·팀 문항 점수, 문항 승리 팀 표시.
   - **묶음 종목 누적 게이지 [필수]:** 묶음 종목에서는 화면 아래에 팀별 누적 게이지를 둡니다. 정답 공개 때마다 이번 문항 점수만큼 게이지가 차오르며 "줄다리기 힘 모으기 2/3 · 토끼팀 187.5 : 154.0 고양이팀"처럼 표시합니다(종목별 이름: 줄다리기 '힘 모으기', 스키점프 '비행 에너지', 스켈레톤 '스타트 파워', 멀리뛰기 '도움닫기 스피드').
   - 경기 장면: 해당 종목 장면(iframe, 10장). 묶음 종목은 3문항 합산 결과로 1회, 문항별 종목은 문항마다 1회.
   - 종목 전환 화면, 최종 결과 화면.
7. 화면 위쪽에 항상 **진행 막대**를 둡니다. 현재 문항 번호, 현재 종목 아이콘, 종목 순서(완료한 종목에는 승리 팀 색 메달)를 보여 줍니다.

### 3.2 학생 화면 `/play` [필수]
1. **입장:** 방 코드(QR로 들어오면 자동 입력), 학번, 이름을 입력하고 `입장` 버튼을 누릅니다.
2. **대기실:** "당신은 **토끼팀**이에요!"와 팀 캐릭터, 팀 색 배경, 현재 팀원 수를 보여 줍니다.
3. **문제 화면:** 문항 번호, 종목 이름(묶음 종목은 "줄다리기 문항 2/3", 발별 종목은 "양궁 3발/5발 · 문항 1/2", 문항별 종목은 "사격 3/N발"), 유형별 입력 UI, 타이머, 긴장 효과(7장)가 나옵니다.
   - OX: 큰 `O`와 `X` 버튼.
   - 4지 선다: 큰 보기 버튼 4개(①~④).
   - 주관식: 글자 수 힌트(8.4 참고), 입력칸, `제출` 버튼. 엔터 키로도 제출할 수 있습니다.
   - 제출하면 바로 잠기고 "제출 완료 · 결과를 기다려요"를 표시합니다. 제출 뒤에는 고칠 수 없습니다(한 번만 제출).
4. **문항 결과:** 내 정답 여부(○/×), 정답, 내 점수(+125.3점처럼), 우리 팀 정답률, 문항 승리 팀. 묶음 종목에서는 우리 팀 누적 점수(예: "힘 모으기 2/3 · 우리 팀 187.5점")도 보여 줍니다.
5. **경기 중:** "앞 화면에서 경기를 보세요" 문구와 함께 경기 결과(예: 묶음 종목 "토끼팀 승! 128.5m vs 117.0m", 문항별 종목 "토끼팀 승! 10점 vs 9점")를 간단히 보여 줍니다.
6. **종목 전환과 최종 결과:** 무대와 같은 내용을 휴대폰에 맞게 줄여서 보여 줍니다. 최종 화면에는 내 기록 요약(정답 수, 평균 정답 시간, 내가 모은 점수)을 함께 보여 줍니다.

### 3.3 공통 디자인 [필수]
- 블록(복셀) 스타일을 유지하고, 팀 색과 블록 토끼·고양이 픽셀 얼굴을 씁니다(장면 키트의 `FACES` 픽셀 데이터 재사용).
- 글꼴: 제목은 Black Han Sans, 본문은 IBM Plex Sans KR, 숫자는 Share Tech Mono(Google Fonts, 대체 글꼴 지정).
- 프로젝터 화면의 문제 글자는 최소 40px, 학생 화면 버튼은 최소 높이 56px.
- 색만으로 정보를 전달하지 않도록 팀 이름과 아이콘을 함께 표시합니다.

## 4. 게임 흐름(상태 전이) [필수]

```
LOBBY(대기실)
  └─ 문항 업로드 완료 + 학생 1명 이상 → [게임 시작]
READY(문항 n 준비: 무대에 "n번 문항 · 종목명" 안내)
  └─ [문제 시작]
QUESTION_OPEN(풀이 중, 타이머)
  └─ 시간 종료 | 모든 학생 제출 | [지금 마감]
QUESTION_CLOSED(채점 완료, 정답 비공개)
  └─ [정답 공개]
REVEAL(정답과 팀 점수 공개, 묶음 종목은 누적 게이지 갱신)
  ├─ 묶음 종목의 1·2번째 문항 → [다음 문제] → READY(같은 종목의 다음 문항)
  └─ 묶음 종목의 마지막 문항 또는 문항별 종목 → [경기 보기]
SCENE(경기 장면 재생 → 장면이 끝나면 done)
  └─ [다음 문제]
      ├─ 같은 종목의 다음 문항(문항별 종목) → READY
      ├─ 종목이 바뀜 → EVENT_SUMMARY(종목 전환 화면) → [다음 종목 시작] → READY
      └─ 마지막 문항 → EVENT_SUMMARY(마지막 종목) → FINAL
FINAL(최종 결과)

[게임 종료]는 LOBBY와 FINAL을 제외한 모든 상태에서 FINAL로 이동합니다(12장).
```

- 상태는 **서버가 기준**입니다. 화면은 서버가 보내는 상태만 그립니다.
- 모든 학생이 제출하면 자동으로 마감합니다. 이때 3초 동안 "모두 제출!" 안내를 보여 줍니다.
- 관리자 화면을 새로 고치거나 다시 접속하면 서버 상태를 받아 현재 화면을 그대로 복원합니다.

## 5. 입장과 팀 편성 [필수]

### 5.1 입장 규칙
- 학번은 숫자 5자리(예: `10203`)가 기본입니다. 관리자 설정에서 4~6자리로 바꿀 수 있습니다. 이름은 한글이나 영문 2~10자입니다.
- 같은 방에서 이미 등록된 학번으로 다시 입장하면 **재접속**으로 처리해 같은 팀과 같은 점수를 유지합니다. 다른 기기에서 같은 학번으로 들어오면 관리자 화면에 "중복 접속" 표시를 하고, 나중에 들어온 접속을 유효한 것으로 봅니다.
- 학생 브라우저의 `localStorage`에 `roomCode + studentNo + token`을 저장해 새로 고침해도 자동으로 재입장합니다(저장이 안 되는 환경에서도 학번을 다시 입력하면 재접속 가능).

### 5.2 자동 팀 배정
- 학생이 입장하면 **인원이 적은 팀**에 배정합니다. 두 팀 인원이 같으면 무작위로 정합니다. 이렇게 하면 두 팀 인원 차이가 항상 1명 이하입니다.
- 관리자가 게임 시작 전에 `팀 무작위 다시 섞기`를 누르면, 전체 학생을 무작위로 섞어 반씩 나눕니다(홀수 인원이면 한 팀이 1명 많음).
- 게임 시작 뒤에 들어온 학생은 인원이 적은 팀에 배정하고, **다음 문항부터** 참여합니다.
- 관리자는 언제든 학생을 다른 팀으로 옮길 수 있습니다. 다만 이미 채점한 문항의 점수는 원래 팀에 남습니다.

## 7. 타이머와 긴장 효과 [필수]

### 7.1 시간
| 유형 | 제한 시간 |
|---|---|
| OX | 15초 |
| 4지 선다 | 20초 |
| 주관식 | 40초 |

- 엑셀의 `제한시간(초)` 값이 있으면 그 값을 씁니다.
- **서버 시계가 기준입니다.** 문제를 시작할 때 서버가 `startedAt`, `endsAt`(서버 시각, ms)과 `serverNow`를 보냅니다. 화면은 `offset = serverNow − Date.now()`로 시계 차이를 보정해 남은 시간을 그립니다.
- 제출은 `endsAt + 500ms`(네트워크 지연 여유)까지 받습니다. 그 뒤에 도착한 제출은 무시합니다.

### 7.2 시각 효과 (학생 화면과 무대 공통)
| 남은 시간 비율 | 효과 |
|---|---|
| 100~50% | 타이머 막대 초록, 차분한 배경 |
| 50~30% | 막대 노랑 |
| 30%~5초 | 막대 주황, 남은 초 숫자 커짐 |
| 마지막 5초 | 막대와 숫자 빨강, 숫자 0.5초 간격 깜박임, 화면 테두리 빨간 맥박, 배경 살짝 흔들림 |
| 마지막 3초 | 화면 가운데에 큰 숫자 `3` `2` `1`이 커졌다 작아짐, 학생 휴대폰 짧은 진동(`navigator.vibrate`, 지원 기기만) |

- `prefers-reduced-motion` 설정을 켠 학생에게는 깜박임과 흔들림 없이 색 변화만 보여 줍니다.

### 7.3 소리 효과 (Web Audio API로 직접 합성, 저작권 음원 미사용)
- 배경 긴장 음악: 짧은 베이스 패턴을 반복하며 빨라집니다. 기본 BPM 90, 남은 시간 10초에 120, 5초에 150.

- 시간이 끝나면 부저, 정답 공개 때는 팀 승리 팡파르(짧은 화음)를 냅니다.

- 음량 조절 슬라이더 [선택].

## 8. 채점과 점수 계산 [필수]

### 8.1 학생 문항 점수
```
정답이면  학생 점수 = 100 + 50 × (남은 시간 ÷ 제한 시간)     → 100.0 ~ 150.0
오답·미제출이면  학생 점수 = 0
```
- 남은 시간 = `endsAt − 서버가 제출을 받은 시각`(0보다 작으면 0). 소수 첫째 자리까지 반올림합니다.
- 예) 제한 20초인 선다 문항을 5초 만에(남은 15초) 맞히면 100 + 50 × 15/20 = **137.5점**.

### 8.2 팀 문항 점수 T (0 ~ 150)
```
T = (그 팀 학생 점수 합) ÷ (문제 시작 때의 팀 인원)
```
- 분모는 **제출하지 않은 학생도 포함한 팀 인원**입니다. 그래서 T에는 **정답률**과 **정답 입력 시간**이 함께 반영되고, 팀 인원이 1명 달라도 공정합니다.
- 함께 보여 주는 값:
  - 정답률 = 정답자 수 ÷ 팀 인원 (예: 11/15 = 73%)
  - 평균 정답 시간 = 정답자들의 풀이 시간 평균(초)
- 예) 토끼팀 15명 중 11명이 평균 6초 만에 맞힘(선다 20초) → 학생 점수 평균 약 135점 → T = 135 × 11 / 15 ≈ **99.0**.

### 8.3 문항 승리 팀
문항 승리 팀은 모든 문항에서 정해 정답 공개 화면과 결과 엑셀에 표시합니다. 문항별 종목(양궁, 사격)에서는 이 팀이 그 발의 승리 팀이 됩니다.
1. T가 높은 팀이 그 문항의 승리 팀입니다.
2. T가 같으면 정답률이 높은 팀, 그것도 같으면 평균 정답 시간이 짧은 팀, 그것도 같으면 가장 먼저 정답을 제출한 학생이 있는 팀이 이깁니다.
3. 두 팀 모두 T = 0이면 **무승부**입니다. 경기 장면에서는 두 팀이 같은 기록을 내거나 함께 실패합니다.

### 8.4 주관식 채점과 글자 수 힌트
- **채점 정규화:** 유니코드 NFC 정규화, 앞뒤 공백 제거, **모든 띄어쓰기 제거**, 영문 소문자화, 문장 부호(`.`, `,`, `·`, `-`, `'`, `"`) 제거를 한 뒤 인정 답 중 하나와 같으면 정답입니다.
  - 예) 정답 `헌법 소원|헌법소원`이면 `헌법소원`, `헌법 소원`, `헌법소원.` 모두 정답.
- **글자 수 힌트:** 첫 번째 인정 답에서 **띄어쓰기는 그대로 두고, 나머지 글자를 모두 `ㅁ`으로** 바꿔 보여 줍니다.

  | 정답 | 힌트 |
  |---|---|
  | 인권 | `ㅁㅁ` |
  | 블록 캐릭터 | `ㅁㅁ ㅁㅁㅁ` |
  | 헌법 소원 | `ㅁㅁ ㅁㅁ` |
  | 시민 불복종 | `ㅁㅁ ㅁㅁㅁ` |

- 학생 화면에는 문제 아래에 `정답 글자 수: ㅁㅁ ㅁㅁㅁ (2글자 · 3글자)`처럼 크게 보여 주고, 무대 화면에도 같은 힌트를 표시합니다. 엑셀 `글자수힌트`가 `N`이면 숨깁니다.
- 숫자·영문이 들어간 답도 한 글자당 `ㅁ` 하나로 바꿉니다(예: `UN` → `ㅁㅁ`).
- 힌트 문자열은 서버가 만들어 보냅니다. **정답 자체는 정답 공개 전까지 학생 기기로 보내지 않습니다.**

### 8.5 묶음 종목 점수와 승리 팀 (줄다리기, 스키점프, 스켈레톤, 멀리뛰기)
```
묶음 점수 S = 그 종목 3문항의 T 합      (0 ~ 450)
```
- 세 문항 각각의 T에 그 문항의 정답률과 입력 시간이 이미 반영되어 있으므로, S는 세 문항 풀이 결과를 팀별로 합산한 점수입니다.
- 함께 보여 주는 값: 3문항 전체 정답률(정답 수 합 ÷ 팀 인원 합), 3문항 평균 정답 시간.
- **S가 큰 팀**이 그 종목의 경기 1회(한 판 당기기, 점프, 주행, 1차 시기)에서 이기고, 그 종목의 승리 팀이 됩니다.
- S가 같으면 3문항 전체 정답률이 높은 팀, 그것도 같으면 3문항 평균 정답 시간이 짧은 팀, 그것도 같으면 무승부입니다.
- 예) 줄다리기 1~3번 문항에서 토끼팀 T = 99.0, 120.5, 68.0 → S = 287.5, 고양이팀 T = 105.0, 80.0, 56.0 → S = 241.0 → 토끼팀이 줄을 당겨 이깁니다.

### 8.6 문항별 종목 승리 팀 (양궁, 사격)
1. 그 종목에서 **이긴 발/문항 수가 많은 팀**이 종목 승리 팀입니다. 양궁은 2문항 T 합이 큰 쪽이 그 발을 이기고(총 5발, 20점 과녁, 1~20점), 사격은 1문항마다 승자를 가립니다.
2. 이긴 문항 수가 같으면 그 종목 문항들의 **T 합이 큰 팀**이 이깁니다. 이때 전환 화면에 "5승 5패 · 문항 점수 합으로 결정"이라고 알려 줍니다.
3. T 합까지 같으면 그 종목은 무승부입니다.

### 8.7 최종 합계와 우승 팀
```
팀 최종 합계 = 진행한 모든 문항의 T 합 + 종목 승리 보너스 × 이긴 종목 수
```
- 종목 승리 보너스는 관리자 설정값입니다(기본 0점, 0~100점). 0이면 문항 점수만으로 우승 팀을 정합니다.
- 합계가 같으면 이긴 종목 수가 많은 팀, 그것도 같으면 전체 평균 정답 시간이 짧은 팀, 그것도 같으면 무승부입니다.
- 모든 점수는 서버에서 계산하고, 소수 첫째 자리까지 표시합니다.

## 9. 종목별 경기 결과 만들기 [필수]

승패는 8장의 점수로 먼저 정해집니다. 경기 장면은 그 결과를 **보여 주기만** 합니다. 장면의 기록(거리, 시간, 과녁 점수)은 아래 규칙으로 만들어, 점수가 높은 팀이 **항상 경기에서 이기게** 합니다.

### 9.1 묶음 종목 (3문항 합산 → 경기 1회)
- `Sw` = 이긴 팀의 묶음 점수, `Sl` = 진 팀의 묶음 점수, `d = (Sw − Sl) ÷ 450` (0~1, 점수 차이 비율).
- 이긴 팀의 기록은 `Sw`가 클수록 좋아지고, 두 팀 기록 차이는 `d`가 클수록 커집니다. 점수 차이가 작으면 아슬아슬한 경기, 크면 일방적인 경기가 됩니다.
- 무승부면 두 팀 기록이 같습니다(줄다리기는 줄이 제자리).

| 종목 | 경기 1회 | 이긴 팀 기록 | 진 팀 기록 | 정답자 0명인 팀(S = 0)의 아쉬운 연출 |
|---|---|---|---|---|
| 줄다리기 | 한 판(4.5초) 당기기 | 줄을 `0.3 + 1.7 × d` m 끌어옴(최대 2.0m). 2.0m에 닿으면 "승리선 통과!" | 같은 거리만큼 끌려감 | 힘을 못 써 앞으로 미끄러지며 끌려감 |
| 스키점프 | 점프 1회 | 거리 = 100 + 39 × (Sw ÷ 450) m (최대 139m) | 이긴 팀 − (2 + 18 × d) m | 낮은 비행, 자세 흔들림 |
| 스켈레톤 | 주행 1회 | 기록 = 58.50 − 3.0 × (Sw ÷ 450) 초 | 이긴 팀 + (0.10 + 1.5 × d) 초 | 벽 접촉 여러 번 |
| 멀리뛰기 | 1차 시기 1회 | 거리 = 6.20 + 1.80 × (Sw ÷ 450) m | 이긴 팀 − (0.05 + 0.80 × d) m | 구름판 한참 뒤에서 도약, 착지 때 엉덩방아 |

- 장면에는 경기 전에 "3문항 합산 · 토끼팀 287.5 : 241.0 고양이팀"을 띄우고 경기를 시작합니다.
- 연출은 겉모습만 바꾸고 기록 값은 표의 규칙을 그대로 따릅니다.

### 9.2 문항별 종목 (양궁, 사격: 1문항 → 1발)
- `Tw` = 그 문항에서 이긴 팀의 T, `Tl` = 진 팀의 T.
- 진 팀의 기록은 **항상 같은 간격만큼** 낮게 만듭니다. 그러면 종목 기록 합계의 차이가 "이긴 문항 수 차이 × 간격"이 되어, 장면의 합계와 8.6의 종목 승패가 어긋나지 않습니다.
- 무승부 문항은 두 팀이 같은 기록을 냅니다.
- 그 팀의 **T = 0**(정답자 없음)이면 "아쉬운 연출"을 보여 줍니다. 연출은 겉모습만 바꾸고, **기록 값은 간격 규칙을 그대로 따릅니다**(0점처럼 값을 바꾸면 장면 합계와 종목 승패가 어긋날 수 있기 때문).

| 종목 | 문항당 경기 | 이긴 팀 기록 | 진 팀 기록(고정 간격) | T = 0인 팀의 아쉬운 연출 |
|---|---|---|---|---|
| 양궁 | 1발 | Tw ≥ 140이면 X(10점), 120 이상 10점, 80 이상 9점, 그 밖 8점 | 이긴 팀 − 1점 | 링 경계선에 아슬아슬하게 꽂힘, 조준 크게 흔들림 |
| 사격 | 1발 | 점수 = 10.0 + 0.006 × Tw (최대 10.9) | 이긴 팀 − 0.4점 | 조준점이 크게 흔들리다 마지막에 겨우 쏨 |

### 9.3 공통
- 각 종목의 장면은 이 표의 값을 받아 그대로 재생합니다. 장면 안의 무작위 요소(흔들림, 자세, 카메라)는 연출에만 씁니다.
- 경기 결과 생성은 서버의 `src/sceneResults.js`에 두고, 단위 테스트로 "이긴 팀 기록이 항상 더 좋다"를 확인합니다.

## 10. 경기 장면 연동 [필수]

### 10.1 사용할 장면 키트
앞서 만든 키트의 압축을 풀어 아래 위치에 둡니다. 키트마다 `index.html`, `three.min.js`, `README.md`(연결 방법)가 들어 있습니다.

| 종목 | 키트 파일 | 넣을 위치 | 키트의 기존 API |
|---|---|---|---|
| 줄다리기 | `tug-duel-kit.zip` | `public/scenes/tug-duel/` | `TugDuel.pull(quality)` |
| 스키점프 | `skijump-duel-kit.zip` | `public/scenes/skijump-duel/` | `SkiJumpDuel.jump(quality)` |
| 스켈레톤 | `skeleton-duel-kit.zip` | `public/scenes/skeleton-duel/` | `SkeletonDuel.run(quality)` |
| 멀리뛰기 | `longjump-duel-kit.zip` | `public/scenes/longjump-duel/` | `LongJumpDuel.jump(quality)` |
| 양궁 | `archery-duel-kit.zip` | `public/scenes/archery-duel/` | `ArcheryDuel.shoot(quality)` |
| 사격 | `pistol-duel-kit.zip` | `public/scenes/pistol-duel/` | `PistolDuel.shoot(quality)` |

- `three.min.js`는 6개 폴더에 똑같이 들어 있으니 `public/scenes/lib/three.min.js` 하나로 합치고, 각 `index.html`의 경로를 고칩니다.
- 무대에는 **현재 종목의 장면 하나만** iframe으로 띄웁니다. 종목이 바뀌면 이전 iframe을 지워 그래픽 메모리를 비웁니다.

### 10.2 장면에 추가할 "결과 재생 모드" (`?mode=app`)
지금 키트들은 `quality`(0~1)에 따라 결과가 **무작위로** 정해집니다. 앱에서는 9장의 결과를 **정확히 재생**해야 하므로, 각 `index.html`에 다음을 추가합니다.

1. 주소에 `?mode=app`이 있으면:
   - 자동 진행을 끄고, 키트 자체의 버튼·전광판·제목을 숨깁니다(`ui=min`과 같음).
   - 키트 자체의 점수 공식, 승부 판정, 우승 배너를 쓰지 않습니다. 진행 횟수는 **묶음 종목은 1회**, 문항별 종목은 문항 수에 맞춥니다.
   - 팀 이름은 `names=토끼팀,고양이팀`으로 받습니다.
2. 새 명령 `playResult`를 추가합니다.
   ```js
   // 관리자 화면 → 장면 iframe
   scene.postMessage({
     type: '<장면 타입>',            // tugDuel, skiJumpDuel, skeletonDuel, longJumpDuel, archeryDuel, pistolDuel
     action: 'playResult',
     mode: 'bundle',                 // 'bundle'(묶음 종목, 경기 1회) | 'perQuestion'(양궁·사격)
     index: 1,                       // 묶음 종목은 항상 1. 문항별 종목은 종목 안에서 몇 번째 발인지(1부터)
     of: 1,                          // 묶음 종목은 1. 문항별 종목은 종목 전체 발 수
     questions: [1, 2, 3],           // 이 경기에 합산된 문항 번호(묶음 종목)
     scores: { rabbit: 287.5, cat: 241.0 },   // 묶음 점수 S(묶음 종목) 또는 문항 점수 T(문항별 종목)
     winner: 'rabbit',               // 'rabbit' | 'cat' | 'draw'
     result: {                       // 9장 표로 만든 값
       rabbit: { value: 0.47, label: '+0.47m', fail: false },
       cat:    { value: -0.47, label: '-0.47m', fail: false }
     }
   }, '*');
   ```
3. 애니메이션과 결과 표시가 끝나면 `done` 이벤트를 보냅니다.
   ```js
   parent.postMessage({ type: '<장면 타입>:event', event: 'done', data: { index: 3 } }, '*');
   ```
4. 종목이 끝나면 `eventSummary`를 받아 종목 결과(묶음 종목 예: "3문항 합산 287.5 : 241.0 · 토끼팀 승리", 문항별 종목 예: "토끼팀 6승 4패")를 장면 안에 잠깐 보여 줍니다.

### 10.3 장면별 수정 사항
| 장면 | 수정 내용 |
|---|---|
| 줄다리기 | **한 판만** 진행합니다(`rounds=1`). `playResult`를 받으면 4.5초 동안 줄을 받은 거리만큼 정확히 움직이고(무승부는 0), 2.0m에 닿으면 승리선 통과 연출을 합니다. 힘 그래프는 이긴 팀이 위에 오도록 연출용으로 만들고, 화면 위에 "3문항 합산 점수"를 표시합니다. |
| 스키점프 | **점프 1회만** 진행합니다. `planJump` 대신 받은 거리로 비행 궤적을 계산합니다. 심판 자세 점수는 연출용으로 쓰되, 표시하는 거리는 받은 값과 같아야 합니다. |
| 스켈레톤 | **주행 1회만** 진행합니다. 결승 기록이 받은 시간과 같아지도록 속도 곡선의 배율을 조정합니다(같은 트랙, 고스트 표시 유지). 구간 기록도 그 비율로 만듭니다. |
| 멀리뛰기 | **1차 시기 1회만** 진행합니다. 받은 거리에 착지합니다. 앱 모드에서는 파울을 쓰지 않고, `fail: true`이면 구름판 뒤에서 도약하고 엉덩방아를 찧는 연출만 합니다. |
| 양궁 | 세트제 대신 **5발 합계 방식**으로 바꿉니다(2문항 합산 = 1발). 과녁은 1~20점의 20개 링(링 폭 3.05cm), 받은 링 안의 무작위 위치에 맞히고 `fail: true`이면 그 링의 경계선 가까이에 꽂힙니다. 전광판은 발별 점수와 합계를 보여 줍니다. |
| 사격 | 탈락제 없이 1문항당 두 팀이 1발씩 쏩니다. 받은 소수 점수(예: 10.4)에 맞는 거리에 탄흔을 만듭니다. 탄흔 거리 = (10.9 − 점수) × 8mm + (0~0.8mm 무작위). |

### 10.4 무대 화면의 장면 진행
- `경기 보기`를 누르면 서버가 결과를 확정해 관리자 화면으로 보내고(`scene:play`), 관리자 화면은 iframe에 `playResult`를 보냅니다. 묶음 종목은 마지막 문항의 정답 공개 뒤에만 `경기 보기`가 켜집니다.
- 묶음 종목의 장면 iframe은 그 종목의 첫 문항을 시작할 때 미리 불러 둡니다(경기 보기 때 바로 재생되도록).
- 장면에서 `done`이 오면 `다음 문제` 버튼을 켭니다. 장면이 10초 안에 `done`을 보내지 않으면 버튼을 켜고 "장면을 건너뛰었어요"라고 표시합니다(장면 오류에 대비).
- 학생 화면에는 같은 결과를 글과 아이콘으로 보여 줍니다.

## 11. 종목 전환 화면 (점수 차이 표시) [필수]

종목의 마지막 문항이 끝나고 `다음 문제`를 누르면, 다음 종목으로 넘어가기 전에 무대와 학생 화면에 다음 내용을 보여 줍니다.

1. **방금 끝난 종목 결과:** 묶음 종목은 "🥇 줄다리기 — 토끼팀 승리 (3문항 합산 287.5 : 241.0)", 문항별 종목은 "🥇 양궁 — 토끼팀 승리 (6승 4패)"와 승리 팀 캐릭터가 메달을 받는 짧은 애니메이션. 묶음 종목은 문항별 T도 작은 표로 함께 보여 줍니다.
2. **누적 점수와 점수 차이(필수):**
   ```
   토끼팀 287.5  :  241.0 고양이팀
   ▶ 토끼팀이 46.5점 앞서 있어요
   ```
   - 점수 막대 2개(팀 색)로 크기를 비교하고, 차이를 숫자로 크게 보여 줍니다. 동점이면 "동점이에요!"라고 표시합니다.
3. **종목 메달 현황:** 지금까지 각 팀이 이긴 종목 수와 종목별 아이콘.
4. **다음 종목 안내:** "다음 종목: 스키점프 (4~6번 문항 · 3문항 합산 점프 1회)"와 `다음 종목 시작` 버튼(관리자만).

## 12. 게임 종료와 최종 결과 [필수]

### 12.1 종료 방법
- 마지막 문항의 장면과 종목 전환 화면이 끝나면 자동으로 최종 결과로 넘어갑니다.
- 관리자가 `게임 종료`를 누르면 확인 뒤 바로 최종 결과로 넘어갑니다.
  - 정답 공개(REVEAL)까지 끝난 문항만 합계에 넣습니다.
  - 풀이 중(QUESTION_OPEN)이거나 마감만 된(QUESTION_CLOSED) 문항은 **합계에서 뺍니다.** 확인 상자에 "진행 중인 n번 문항은 점수에 넣지 않아요"라고 알려 줍니다.
  - 진행 중이던 종목은 그때까지 정답 공개를 마친 문항으로 종목 승패를 정합니다. 묶음 종목은 끝낸 문항(1~2개)의 T 합으로(8.5), 문항별 종목은 이긴 문항 수로(8.6) 정하고, 표에 "부분 진행(2/3문항)"처럼 표시합니다. 이때 경기 장면은 재생하지 않습니다. 한 문항도 끝내지 못한 종목은 "미진행"으로 표시합니다.

### 12.2 최종 결과 화면
- 8.7 규칙으로 최종 합계를 자동 계산해 **우승 팀**을 크게 알려 줍니다. 승리 팀 블록 캐릭터들이 시상대에서 뛰고, 꽃가루와 팡파르가 나옵니다.
- 표: 종목별 결과(종목, 문항 범위, 방식, 묶음 종목은 팀별 S와 경기 기록 / 문항별 종목은 팀별 승 수, 종목 승리 팀), 팀별 최종 합계와 차이, 전체 정답률, 평균 정답 시간.
- [선택] 팀별 "점수 기여 TOP 3" 학생(관리자 설정에서 켜고 끌 수 있음, 기본은 끔).
- 학생 화면: 우리 팀 승패, 내 기록 요약(정답 수/진행 문항 수, 평균 정답 시간, 내가 모은 점수).

### 12.3 결과 내보내기 [필수]
관리자의 `결과 엑셀 내려받기` 버튼으로 `형성평가결과_방코드_날짜.xlsx`를 만듭니다.

| 시트 | 내용 |
|---|---|
| 요약 | 날짜, 문항 수, 진행 문항 수, 팀별 최종 합계, 우승 팀, 종목별 승리 팀 |
| 학생별 | 학번, 이름, 팀, 문항별 정답 여부(○/×/미제출), 문항별 점수, 정답 수, 평균 정답 시간, 합계 |
| 문항별 | 번호, 유형, 문제, 정답, 전체 정답률, 팀별 정답률·평균 시간·T, 문항 승리 팀, 종목 |
| 종목별 | 종목, 문항 범위, 방식(묶음/문항별), 팀별 T 합(묶음 종목은 S), 팀별 승 수(문항별 종목), 경기 기록(거리·시간·과녁 점수), 종목 승리 팀 |

- 학생별 시트는 학생부 기록이나 보충 지도에 쓸 수 있도록 학번 순으로 정렬합니다.

| `event:summary` | 모두 | `{ sport, mode, questions, S?, wins?, Tsum, record, winner, status, totals, diff, medals, next }` |
| `game:final` | 모두 | `{ totals, winner, events[], stats }` + 학생 개인 요약 |

## 16. 보안, 개인정보, 안정성 [필수]

- 관리자 기능은 `ADMIN_PIN` 인증 뒤에만 쓸 수 있습니다. 모든 `admin:*` 이벤트에서 토큰을 확인합니다.
- 정답은 정답 공개 전까지 서버에만 있습니다. 학생이 받는 문항 데이터에는 정답, 해설, 다른 학생의 답이 없습니다.
- 학생에게는 다른 학생의 학번과 이름을 보내지 않습니다(팀 인원 수만).
- 학번과 이름은 수업 진행과 결과 내보내기에만 쓰고, 외부 서비스로 보내지 않습니다. 방을 초기화하면 지웁니다.
- 입력값 검증: 이름 길이와 글자, 학번 자릿수, 답안 길이(주관식 최대 50자)를 확인하고, HTML로 표시할 때는 반드시 이스케이프합니다.
- 연결이 끊긴 학생은 재접속하면 현재 상태를 받습니다. 풀이 중에 다시 들어오면 남은 시간만큼 이어서 풀 수 있습니다(이미 제출했다면 "제출 완료").
- 35명이 동시에 접속하고 제출해도 지연 없이 동작해야 합니다(19장 봇 테스트).

## 18. 단위 테스트에 꼭 넣을 경우

- 학생 점수: 남은 시간 0초, 제한 시간과 같음, 마감 직후 0.4초에 도착(유효), 0.6초에 도착(무효).
- 팀 점수 T: 미제출 학생이 있을 때 분모가 팀 인원인지 확인.
- 문항 승리 동점 처리 4단계와 두 팀 모두 0점인 무승부.
- 묶음 점수 S: 3문항 T 합이 맞는지, S 동점일 때 정답률 → 평균 시간 순으로 결정, 모두 같으면 무승부.
- 문항별 종목 승패: 5승 5패에서 T 합으로 결정, T 합도 같으면 무승부.
- 최종 합계: 종목 승리 보너스 0점과 50점일 때.
- 묶음 종목 중간 종료: 2/3문항에서 `게임 종료` 시 2문항 T 합으로 종목 승패가 정해지고 장면은 재생되지 않음.
- 정규화: `헌법 소원` = `헌법소원` = ` 헌법소원. `.
- 힌트: `인권` → `ㅁㅁ`, `블록 캐릭터` → `ㅁㅁ ㅁㅁㅁ`, `UN 헌장` → `ㅁㅁ ㅁㅁ`.
- 문항 수별 종목 매핑: 1개, 3개, 4개, 11개(멀리뛰기 2문항 합산), 12개, 13개, 22개, 23개, 30개.
- `sceneResults`: 묶음 종목은 S가 큰 팀의 기록이 항상 더 좋고 점수 차이가 클수록 기록 차이도 큼(줄다리기는 최대 2.0m). 양궁·사격은 이긴 팀 기록이 더 좋고, 종목 기록 합계의 차이가 "이긴 문항 수 차이 × 간격"과 같음(T = 0인 팀이 있어도). 무승부는 두 팀 기록이 같음.

## 부록 B. 용어
- **T(팀 문항 점수):** 팀 학생 점수 합 ÷ 팀 인원(0~150).
- **묶음 종목:** 3문항을 풀고 T를 합산해 경기를 1회 치르는 종목(줄다리기, 스키점프, 스켈레톤, 멀리뛰기).
- **묶음 점수 S:** 묶음 종목 3문항의 T 합(0~450). S가 큰 팀이 그 종목의 경기와 종목에서 이김.
- **문항별 종목:** 문항마다 1발씩 겨루는 종목(양궁, 사격).
- **문항 승리 팀:** 한 문항에서 T가 높은 팀. 문항별 종목에서는 그 발의 경기에서 이기는 팀.
- **종목 승리 팀:** 묶음 종목은 S가 큰 팀, 문항별 종목은 이긴 문항이 많은 팀(같으면 T 합).
- **최종 합계:** 진행한 문항의 T 합 + 종목 승리 보너스.
